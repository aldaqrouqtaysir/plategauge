# Maintaining PlateGauge

Start with [current release status](CURRENT_RELEASE.md). A passing source build
does not replace the live archive or authorize scientific changes. Existing
release folders, release workflows, tags, media and evidence remain historical
records. New operational requirements use a separately tested successor.

## Dependency updates

Python updates use Dependabot's `uv` ecosystem so `pyproject.toml` and `uv.lock`
can be reviewed together. Keep the pinned uv version and `uv sync --locked`;
never regenerate the lock in CI to make an incompatible proposal pass. Check
that a proposed update works with the repository's lock format and pinned tool.
Old pip-only proposals without a matching lock update are not merge-ready.

The GitHub Actions updater excludes the exact existing frozen release-workflow
paths in `.github/dependabot.yml`. This prevents automatic historical rewrites,
not security review. Ordinary CI remains eligible for updates. If a retained
release tool needs a security or runtime correction, create a new operations
profile with explicit pins and its own verification; do not rewrite published
records or silently move a tag. Add the new exact paths to the preservation list
once that successor is frozen. Avoid a blanket wildcard that silently excludes
all future work. Review major upgrades individually and keep failed checks.

References: GitHub's [supported ecosystems](https://docs.github.com/en/code-security/reference/supply-chain-security/supported-ecosystems-and-repositories)
and [path exclusions](https://docs.github.com/en/code-security/reference/supply-chain-security/dependabot-options-reference#exclude-paths).

## Release-operations regression checks

Ordinary CI separately discovers bounded `release/camera` and `release/camera-rN`
directories and checks their synthetic stdlib tests, Python types/lint and
TypeScript harnesses. It rejects incomplete profiles, links and unexpected names.
These checks do not inspect datasets, execute models, visit a website, deploy,
or manufacture approval. Existing delivery and live checks are still required.

With the locked development environment and web dependencies installed, run
from the repository root:

```text
uv run --locked python scripts/verify_release_operations.py --phase synthetic
uv run --locked python scripts/verify_release_operations.py --phase typing
```

## New screenshots and recordings

`pnpm capture:portfolio` and `pnpm record:demo` are **benchmark-only authoring
recipes**, not camera demos or release checks. Both require `--output` naming a
new absolute directory outside this checkout, with an existing ordinary parent.
They reject an existing destination, symlink/junction ancestry, checkout paths
and parent directories containing the checkout. They never overwrite the old
`reports/media` evidence. Preserve failed attempts and choose a fresh directory
for a retry. No media is generated by ordinary CI.

For example, from `web/`, with an independently verified benchmark preview on
loopback port 4177 and a current matching static audit:

```text
pnpm capture:portfolio --output <absolute-new-directory> --bundle <absolute-benchmark-dist> --static-audit <absolute-matching-audit-json>
pnpm record:demo --output <another-absolute-new-directory>
```

Replace every placeholder before running. The recording uses the current UTC
date; its captioned local-review narrative does not establish deployment or
camera accuracy. Review generated media and record new provenance before
publishing it under new names. Never update historical hashes to bless new media.
